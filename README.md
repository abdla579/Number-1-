# مساعد صيانة الموبايل 📱🔧

تطبيق أندرويد لفنيي صيانة الموبايل: بحث عن موديل الهاتف، عرض قطع الغيار
وأسعارها، الأكواد المهمة، ومخطط الهاتف (PDF).

---

## 1) إزاي تشغّل المشروع على GitHub (من الهاتف بالكامل)

1. اعمل حساب على [github.com](https://github.com) لو مفيش عندك.
2. اعمل Repository جديد (زرار New) — سيبه Public أو Private زي ما تحب.
3. ارفع كل ملفات المشروع ده (نفس بنية المجلدات كما هي) داخل الـ Repository.
   - من الهاتف: تقدر تستخدم تطبيق GitHub الرسمي، أو تفتح github.com من المتصفح
     وتستخدم خاصية "Add file > Upload files" وتسحب كل المجلد.
4. بمجرد ما ترفع الملفات على فرع `main`، هيشتغل GitHub Actions تلقائيًا
   ويبدأ يبني التطبيق (تقدر تتابعه من تبويب **Actions** فوق الـ Repository).
5. لما يخلص (يستغرق حوالي 3-6 دقايق)، هتلاقي ملف APK جاهز تحت اسم
   **mobile-repair-app-apk** في نفس صفحة الـ Actions (Artifacts) — نزّله
   وثبّته على أي هاتف أندرويد (لازم تفعّل "تثبيت من مصادر غير معروفة" أول مرة).

---

## 2) إزاي تضيف موديلات وأسعار جديدة

كل البيانات موجودة في ملف واحد بسيط:

```
assets/data/parts_data.json
```

افتحه وانسخ نفس شكل أي موديل موجود وعدّل القيم:

```json
{
  "id": "iphone_11",
  "brand": "Apple",
  "model": "iPhone 11",
  "notes": "أي ملاحظة عامة عن الموديل ده",
  "schematic_file": "iphone_11.pdf",
  "parts": [
    {"name": "شاشة", "price": "650", "quality": "كوبي A", "notes": ""}
  ],
  "codes": [
    {"type": "كود الفورمات", "value": "*2767*3855#", "description": "وصف مختصر"}
  ]
}
```

- **id**: اسم فريد بالإنجليزي بدون مسافات (يستخدم داخليًا فقط).
- **schematic_file**: اسم ملف الـ PDF بتاع المخطط (لازم يطابق اسم الملف
  اللي هتحطه في الخطوة الجاية بالظبط، حروف كبيرة/صغيرة مهمة).
- ممكن تضيف أي عدد موديلات جديدة داخل مصفوفة `"phones": [...]`.

بعد أي تعديل في الملف، ارفعه (commit) على GitHub وهيبني نسخة APK جديدة تلقائيًا.

---

## 3) إزاي تضيف مخططات PDF

1. حط ملف الـ PDF داخل مجلد:
   ```
   assets/schematics/
   ```
2. تأكد إن اسم الملف مطابق تمامًا لقيمة `schematic_file` في ملف الـ JSON.
3. ارفع الملف على GitHub زي أي ملف تاني — مش محتاج تعديل إضافي، المجلد
   كله بيتضاف تلقائيًا للتطبيق (مكتوب في `pubspec.yaml`).

---

## 4) تعديل اسم التطبيق

غيّر القيمة `name:` و `description:` في أول ملف `pubspec.yaml`، وكمان لو
حبيت تغيّر الاسم الظاهر تحت أيقونة التطبيق على الهاتف، عدّل قيمة
`android:label` في ملف `android/app/src/main/AndroidManifest.xml` بعد
ما يتولّد أول مرة من الـ workflow (أو أضفه يدويًا لاحقًا).

---

## 5) بنية المشروع

```
lib/
  main.dart                     نقطة تشغيل التطبيق
  models/phone_model.dart       تعريف شكل البيانات (هاتف، قطعة، كود)
  data/data_loader.dart         قراءة وبحث داخل ملف JSON
  screens/home_screen.dart      شاشة البحث الرئيسية
  screens/model_detail_screen.dart  تفاصيل الموديل (تابات: قطع/أكواد/مخطط)
  screens/pdf_viewer_screen.dart    عرض ملف PDF المخطط
assets/
  data/parts_data.json          بيانات الأسعار والموديلات (عدّل هنا)
  schematics/                   ملفات PDF المخططات (ضيف هنا)
.github/workflows/build.yml     أتمتة بناء APK على GitHub Actions
```

---

## 6) ملاحظات

- التطبيق كله يشتغل **بدون إنترنت** بعد التثبيت — البيانات كلها محفوظة
  جوه التطبيق نفسه.
- تحديث الأسعار = تعديل ملف JSON واحد + رفعه على GitHub، والباقي أوتوماتيك.
- لو عايز مستقبلًا شاشة "تعديل من داخل التطبيق نفسه" بدل تعديل الملف،
  ده تطوير إضافي (يحتاج قاعدة بيانات محلية زي SQLite بدل JSON الثابت).
